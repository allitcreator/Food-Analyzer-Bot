# Шорткаты iOS для телеграм-бота: что работает, а что молча ломается

Практическое руководство, добытое двумя днями отладки в этом проекте. Если делаете
похожую «быструю запись с телефона» для другого бота — читать до того, как писать код,
иначе повторите весь путь.

Рабочий пример целиком: `scripts/build-shortcuts.py` (генератор), `server/quick-api.ts`
(приём), `server/lib/quick-binary.ts` (бинарное тело), `server/lib/quick-reject-log.ts`
(диагностика отказов).

---

## Главное правило

**Надёжно работают только подстановки переменных в строковые поля и ссылка на результат
в поле файла. Любое промежуточное действие между источником и потребителем может молча
вернуть пустоту.**

В нашем случае пустоту вернули все до единого:

| Действие | Что делало | Итог |
|---|---|---|
| `is.workflow.actions.image.resize` | уменьшить до 1280 px | пустой результат |
| `is.workflow.actions.image.convert` | в JPEG с качеством 0.7 | пустой результат |
| `is.workflow.actions.base64encode` | закодировать снимок | пустая строка |
| `is.workflow.actions.urlencode` | закодировать подпись | пустая строка |
| `is.workflow.actions.gettext` для сборки URL | склеить адрес с подписью | запрос не ушёл вовсе |

Ошибку при этом не показывает никто: Shortcuts подставляет пустое значение и спокойно
идёт дальше. Уведомление «Отправил» приходит даже когда не отправилось ничего.

**Вывод для архитектуры:** держите шорткат максимально коротким, а всю обработку —
уменьшение, конвертацию, кодирование — переносите на сервер. Итоговая фото-ветка у нас
состоит из трёх шагов: снять, спросить подпись, отправить.

Добавляете действие — добавляйте по одному и проверяйте прогоном. Иначе при неудаче
непонятно, какое из них виновато.

## Что точно работает

- **Подстановка переменной в строковое поле.** Заголовок `Authorization`, адрес URL,
  значение в JSON-теле. Механизм — `WFTextTokenString` со строкой из символа U+FFFC
  и словарём `attachmentsByRange`, где ключ — позиция в UTF-16, а значение — ссылка
  `{Type: ActionOutput, OutputUUID, OutputName}`.
- **Ссылка на результат в поле файла** (`WFRequestVariable`) — через
  `WFTextTokenAttachment`, где всё поле целиком и есть ссылка.
- **Интерактивные действия:** «Запросить ввод» (`ask`), «Диктовать текст» (`dictatetext`),
  «Сделать фото» (`takephoto`), меню (`choosefrommenu`), уведомление, показ результата.
- **Вопрос при импорте** (`WFWorkflowImportQuestions`) — телефон сам спрашивает значение
  при установке и кладёт его в указанный параметр действия.

## Подпись файла

С iOS 15 неподписанный `.shortcut` телефон не импортирует. Подпись ставит только macOS:

```bash
python3 scripts/build-shortcuts.py
shortcuts sign -m anyone -i shortcuts/eda-full.unsigned.shortcut -o "shortcuts/Еда.shortcut"
```

Следствия, важные для архитектуры:

- **Собрать персональный файл на Linux-сервере нельзя.** Забудьте про «сгенерируем
  шорткат с уже вшитым токеном» — подпись покрывает содержимое, её пришлось бы ставить
  на каждого пользователя.
- Утилита ходит в сеть и иногда падает с `NSURLErrorDomain error 500` — просто повторите.
- Строки `ERROR: Unrecognized attribute string flag` в выводе — её обычный шум, файл
  при этом создаётся.
- Имя файла становится именем шортката на телефоне, так что называйте по-человечески.

Бот раздаёт готовый подписанный файл документом, а Dockerfile кладёт каталог в образ:

```dockerfile
COPY --from=builder /app/shortcuts ./shortcuts
```

## Токен: вопрос при импорте

Раз вшить токен нельзя, пользователь должен вставить его сам. Не заставляйте его лазить
в заголовки — для этого есть штатный механизм.

Кладём токен в отдельное действие «Текст» в начале шортката, а заголовок собираем из
него подстановкой:

```python
token_text(uuid)        # gettext с плейсхолдером, CustomOutputName "Токен"
mixed_value("Bearer ", token_uuid, "Токен")   # значение заголовка Authorization
```

И описываем вопрос, который телефон задаст при установке:

```python
{
    "ActionIndex": <позиция действия «Текст» в массиве>,
    "Category": "Parameter",
    "ParameterKey": "WFTextActionText",
    "Text": "Вставь токен быстрой записи",
}
```

`ActionIndex` считайте от массива действий, а не хардкодьте: порядок меняется при любой
правке сценария. И проверяйте его на сборке — битый индекс молча ничего не спросит, и
человек получит шорткат с плейсхолдером вместо токена.

**Слово `Bearer` в плейсхолдер не кладите.** Если пользователь скопирует строку целиком,
получится `Bearer Bearer abc…` и сервер вернёт 401. Пусть в поле едет только токен, а
схема добавляется в заголовке.

## Фото: только бинарём

Не гоняйте картинку через base64. Строка на 300+ КБ — то самое место, где всё ломается,
плюс лишняя треть объёма.

В шорткате — режим тела «файл»:

```python
{
    "WFHTTPBodyType": "File",
    "WFRequestVariable": attachment_value(photo_uuid, "Снимок"),
}
```

Подпись к фото тогда едет в query (`?text=`) подстановкой прямо из «Запросить ввод».
Процентное кодирование Shortcuts делает сам — отдельное действие для этого не нужно и
вредно.

**Поле `WFURL` не принимает ссылку на другое действие.** Адрес задавайте строкой, при
необходимости с подстановкой внутри. Со ссылкой запрос не уходит вообще, и в логах не
остаётся ни следа.

## Серверная сторона

**Читайте как байты всё, что не JSON.** Перечислять типы бесполезно: шорткат прислал
файл с `Content-Type`, которого не было в нашем списке `image/*`, и запрос остался
вообще без тела.

```ts
express.raw({ type: (req) => isBinaryContentType(req.headers["content-type"]), limit: "10mb" })
```

**Не раздваивайте контракт.** Бинарное тело приводится к тому же объекту, что приезжает
в JSON-варианте, и проходит ту же схему — правила про размер, пустоту и подпись остаются
одни.

**Согласуйте лимиты по всей цепочке**, иначе будете ловить `413` в неожиданном месте:
nginx `client_max_body_size` → лимит парсера тела → лимит в схеме валидации → лимит
принимающего API (у Telegram `sendPhoto` это 10 МБ). Помните, что отсечка в nginx
срабатывает до проверки токена, то есть защищает и от неавторизованных запросов —
не завышайте её без нужды.

**Проверяйте формат по сигнатуре.** iPhone умеет снимать в HEIC, а Telegram такой файл
не примет. Без проверки отказ прилетит из `sendPhoto` и будет выглядеть как «опять
ничего не пришло».

## Отладка: логи сервера — единственный источник правды

Шорткат ошибку не покажет: действие «Получить содержимое URL» на 4xx не прерывается, а
молча отдаёт тело ответа и идёт дальше. С телефона видно только то, что результат не
пришёл.

Поэтому **логируйте причину каждого отказа**:

```
[quick] auth rejected: header_len=55 scheme=Bearer placeholder=yes parsed=no
[quick] rejected: binary=3968174 ct=image/jpeg imageBase64=5290900 issues=[too_big@imageBase64]
[quick] accepted: binary=4087052 kind=jpeg caption=12
```

Что писать: длины полей, набор ключей, коды ошибок, `Content-Type`, стадию отказа.
Что не писать: содержимое. `imageBase64` — это мегабайты мусора, подпись к еде — личные
данные, токен — полный доступ к дневнику.

Такой лог экономит целый цикл «пересобрал → подписал → переставил на телефон → снял
кадр». У нас он за один прогон закрыл вопрос, на который до этого ушло несколько итераций.

## Проверка при сборке

Ошибки в plist молчаливые, поэтому ловите их до подписи. `validate()` в генераторе
проверяет:

- каждая ссылка на выход указывает на действие, объявленное **выше**;
- числовые поля записаны строками (`"1280"`, а не `1280`);
- `ActionIndex` вопроса импорта в границах массива, а названный параметр у этого
  действия существует.

Проверяйте валидатор обратным тестом — сломайте ссылку намеренно и убедитесь, что сборка
падает. Иначе однажды окажется, что он ничего не проверяет.

## Чек-лист новой интеграции

1. Эндпоинт с токеном в заголовке (не в URL — утечёт в логи nginx).
2. Генератор шортката на `plistlib` + `validate()`.
3. Токен через `WFWorkflowImportQuestions`.
4. Фото — бинарём, обработка на сервере.
5. Подпись `shortcuts sign -m anyone`, файл в репозиторий и в Docker-образ.
6. Команда бота, которая присылает файл; токен — отдельным сообщением, чтобы копировался
   одним тапом.
7. Логи отказов с длинами и кодами, без содержимого.
8. Инструкция в боте — два шага, не десять. Длинную никто не читает.
