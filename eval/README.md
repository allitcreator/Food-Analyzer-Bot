# Eval моделей

Ручной прогон реальных функций `server/openai.ts` на разных моделях OpenRouter.
В `npm test` не входит: ходит в сеть и тратит деньги. В `npm test` входят только
чистые метрики (`tests/eval-metrics.test.ts`).

## Запуск

```bash
OPENROUTER_API_KEY=... npx tsx scripts/eval-models.ts --task text \
  --models openai/gpt-4o-mini,openai/gpt-6-luna,anthropic/claude-haiku-5.5 --repeat 3
```

| Флаг | Что делает |
| --- | --- |
| `--task text\|photo\|voice` | обязательный |
| `--models a,b` | id моделей OpenRouter; по умолчанию текущая модель роли из конфига |
| `--repeat N` | сколько раз прогнать каждый кейс (разброс ответов), по умолчанию 1 |
| `--limit N` | только первые N кейсов — для пробного запуска |
| `--concurrency N` | параллельных кейсов, по умолчанию 4 |
| `--reasoning none\|minimal\|low\|medium\|high` | перекрыть уровень reasoning (как `AI_REASONING_EFFORT`) |

Ключ берётся только из `OPENROUTER_API_KEY` в окружении и никуда не пишется.
Без ключа скрипт сразу завершится с ошибкой. Сначала запустите с `--limit 5`,
чтобы проверить, что модель вообще отвечает: id модели с опечаткой даст 400 и
нулевую долю ответов.

Модель подменяется через `config.aiModels` — тот же путь, что `AI_MODEL_*` в
проде, поэтому промпты и параметры (temperature, reasoning, max_tokens) те же,
что увидит бот. Fallback-модели (`AI_FALLBACK_*`) на время eval выключены.

Роли: `text` → `AI_MODEL_TEXT` (classifyIntent, analyzeFoodText, analyzeWorkout),
`photo` → `AI_MODEL_VISION` (analyzeFoodImage), `voice` → `AI_MODEL_AUDIO`
(transcribeVoice, с нарезкой длинных голосовых через ffmpeg).

## Результаты

`eval/results/<дата>/<task>-<время>/` (в `.gitignore`):

- `raw.jsonl` — по строке на кейс и повтор: что вернула функция, сырой ответ
  модели, латентность;
- `summary.md` — итоговая таблица, она же печатается в консоль.

В консоль тексты ответов не выводятся, только метрики.

## Метрики

Общие для всех задач:

- **ошибок кейсов** — кейсы, упавшие исключением (битый эталон, нет файла); прогон при этом продолжается;
- **ответов** — сколько вызовов получили ответ API (остальные упали после ретраев);
- **p50 / p95** — латентность вызова функции, вместе с ретраями;
- **стоимость** — сумма `usage.cost` из ответов OpenRouter (приходит в каждом
  ответе автоматически, `usage: {include: true}` устарел), и на один кейс; если
  в части ответов `cost` нет, сумма показана как нижняя граница;
- **reasoning ток./вызов** — `usage.completion_tokens_details.reasoning_tokens`:
  если тут не ноль, reasoning не выключился и мы платим за скрытые токены.
  Моделям, у которых reasoning не выключается, бот добавляет 1024 токена к
  `max_tokens` (см. `server/lib/ai-models.ts`).

`text` и `photo`:

- **валидный JSON** — доля ответивших вызовов, ответ которых парсится как JSON;
- **precision / recall** — позиции ответа против эталона (precision — только по
  вызовам, где API ответил). Названия сопоставляются
  нечётко: слова с грубым стеммингом и триграммы символов, порог 0,5, плюс
  `aliases` эталона;
- **MAPE ккал** — средняя относительная ошибка калорий от середины эталонного
  диапазона по сопоставленным позициям (эталоны меньше 20 ккал — вода, чай — не
  считаются, их видно по попаданию в диапазон);
- **ккал в диапазоне**, **БЖУ в диапазоне** — доля попаданий в эталонный диапазон;
- **MAPE суммы** — ошибка суммы калорий кейса; не зависит от того, разбила модель
  «пюре с котлетой» на две позиции или оставила одну;
- **MAE Б/Ж/У** — средняя абсолютная ошибка в граммах от середины диапазона;
- **hydrating**, **mealType** — точность флага воды и приёма пищи (mealType
  проверяется только там, где он явно указан в тексте).

Только `text`: **intent** — точность `classifyIntent`, **тренировка ккал** —
попадание `analyzeWorkout` в диапазон сожжённых калорий (вес 70 кг).

Только `voice`: **CER** — character error rate по нормализованному тексту
(регистр, ё, пунктуация не считаются), минимальный по списку допустимых
эталонов; **CER > 60 с** — то же для голосовых длиннее минуты, которые бот режет
на куски по 55 с.

## Данные

### Текст — `cases/text.json`

80 кейсов: простые, с граммами, несколько блюд и приёмов пищи, разговорные
количества («полтарелки борща»), напитки и вода, алкоголь, тренировки, смешанные
и шум. Эталоны приблизительные (`reference: "approx"`): типичная порция по
справочным значениям, диапазоны с запасом 25–50%. Время запроса фиксировано
13:00. Поле `note` объясняет спорные кейсы.

Формат позиции: `name`, `aliases`, `weight`/`calories`/`protein`/`fat`/`carbs`
как `[min, max]`, `hydrating`, необязательный `mealType`. У тренировок —
`workout.caloriesBurned: [min, max]`.

### Фото — `photos/`

Фото личные, поэтому вся папка, кроме `manifest.example.json`, в `.gitignore`.

1. Сфотографируйте еду, которую взвесили на весах или КБЖУ которой есть на
   этикетке. Лучше 20–40 фото: одиночные продукты, тарелки из нескольких блюд,
   упаковки, напитки, вода.
2. Положите JPEG в `eval/photos/`.
3. Скопируйте `manifest.example.json` в `manifest.json` и опишите каждое фото:
   `file`, необязательная `caption` (подпись, как пользователь пишет в боте),
   `source` (`label` — этикетка, `scale` — весы, `approx` — на глаз),
   `expected` — позиции в том же формате, что в текстовых кейсах. Для весов и
   этикетки ставьте узкий диапазон (±5–10%).
4. `npx tsx scripts/eval-models.ts --task photo --models ...`

### Голос — `voice/`

19 синтетических голосовых OGG/Opus (mono, 48 кГц, как в Telegram), три из них
длиннее 60 с, чтобы проверить нарезку. Сгенерированы из `voice/phrases.json`
macOS-голосом Milena; `voice/manifest.json` — длительность и допустимые
эталонные расшифровки (числа словами и цифрами).

Перегенерировать (нужны macOS `say` с русским голосом и ffmpeg с libopus):

```bash
npx tsx scripts/eval/generate-voice.ts
```

Синтетика чище живой речи: CER на ней — нижняя граница. Для честной оценки
добавьте несколько своих голосовых (Telegram → сохранить файл) в `voice/` под
именами `personal-*.ogg` и опишите их в `voice/manifest.personal.json` (оба в
`.gitignore`) в том же формате, что `manifest.json`:
`{"items": [{"id", "file", "durationSec", "references": ["..."]}]}`. Eval читает
оба манифеста, генератор личный не трогает.
